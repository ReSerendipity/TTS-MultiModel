1.3 ★ 1.25 GB 单库体积的真相：单批脏数据（本次评估最大发现）

dbstat 页级分析：generation_history 表的 overflow 页 305,980 页 = 1,253.3 MB，leaf 仅 41 页（0.2 MB）。 定位：64 条记录（id 273~336，voxcpm2 63 条 + qwen3tts 1 条）的 output_format 字段被写入了音频 PCM 波形字节（字段长度 33 万~1,677 万字符不等）。 64 条 created_timestamp 完全相同（2026-07-31） → 同一批次写入（疑似某次批量重放/同步的引擎侧 bug 遗留）。 当前 137 行的逻辑数据合计仅约 23 KB —— 库体积的 99.99% 是这 64 条脏数据。

数据口径：主库 1,253.4 MB = 脏记录 overflow 1,252.1 MB + 正常表页 ≈1.3 MB（FTS 0.1 + 各表 leaf 页）+ freelist 50 页。WAL/SHM 285 KB 未计入主库。

⑤ 三个必答问题

问题一：keep_days: 0 + pii_encryption_enabled: false + pii_retention_days: 90 如何共存？

逐条差异：

  • keep_days: 0 → prune_old_records 启动调用但直接 return（不裁剪）——"永久保留"声明与代码一致。
  • pii_encryption_enabled: false → text_preview 明文落库——声明（关闭加密）与代码一致，但与"PII 治理"目标相悖。
  • pii_retention_days: 90 → 被 app_server.py:378 启动路径真实消费，删除超 90 天记录+音频。实测删除过 268 条、现存记录全部 <90 天 → 这条不是空承诺，它在执行。

真正的问题：第 1 条与第 3 条语义相反（保留 vs 删除）且同时生效；第 2 条使删除动作作用于明文 PII。三者共同构成一个自相矛盾的留存矩阵。

对外承诺违约风险：PRIVACY_POLICY.md 声明"可随时清空"与"不收集任何个人信息"——实际明文留存全部输入原文、90 天自动删除且政策未披露留存期限。构成表述性违约风险："可随时清空" ≠ "90 天自动删除"，用户在政策下无法预期数据生命周期。

问题二：哈希链在"密钥与库同目录明文"前提下还剩多少防护价值？

实际防护价值评估：接近零。

  • 攻击者拿到 data/ 目录即同时拿到 .history_hmac_key（64B 明文）与 history.db → 可重新计算任意记录的 HMAC，链形同虚设。
  • 即便密钥安全：verify_chain_integrity 零调用（只写不验）、链仅覆盖 19/137、purge 删除不重算后继 → 当前库运行校验会报大面积 tampered（实测自 id=236 起全断），"防篡改"能力实际未落地。

低成本改进（按性价比排序）：

  • ① 密钥移出 data/（如 ~/.config/tts-multimodel/，权限 0600，.gitignore），与库隔离 —— 一行路径改动，恢复链的基本价值。
  • ② 启动时调用一次 verify_chain_integrity() 并记录告警（已有实现，缺调用点）—— 让"防篡改"从理论变为可观测。
  • ③ purge/delete 后重算受影响后继节点的 prev_hash（或改为逻辑删除），维持链连续性。
  • ④ insert_batch（sync 路径）补 HMAC 计算；旧记录一次性回填。

问题三：训练血缘能否回答"这个 checkpoint 用了哪些数据/代码/超参"？

答案：不能。实测证据：

  • 无任何训练产物（lora/ 空、checkpoints/ 仅 HF 缓存）→ 没有"这个 checkpoint"存在。
  • 血缘字段（dataset_fingerprint / git_commit / config_snapshot_hash）虽已在 TrainingState 定义，但 git_commit/config_snapshot_hash 全项目无赋值点、build_dataloaders 的指纹返回值无接收方、训练脚本走 vendor voxcpm 管线（不 import app 内 training 模块）→ 即使训练成功，血缘也不会写入。

最小可行血缘方案（不引入 DVC）：

  • ① 在 save_checkpoint 时把 {dataset_fingerprint, git_commit(动态取,非空串), config_snapshot_hash, 超参 JSON} 写入 state.json（字段已存在，只需接线）。
  • ② 训练入口（routes/training.py start）从 build_dataloaders 返回值接收 fingerprint 并注入 TrainingState（一行接线）。
  • ③ LoRA 元数据保存时填充 git_commit/dataset_fingerprint（当前硬编码空串，lora.py:176-177）。
  • ④ 产物目录与 config 解耦：明确 checkpoint_dir（现为断点续跑配置）与训练 save_path 的关系，避免路径误读。
