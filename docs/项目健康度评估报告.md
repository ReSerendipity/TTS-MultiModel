# TTS_MultiModel 项目健康度评估报告

> **项目类型**：开源（Apache-2.0）  
> **技术栈**：Python 3.10+ + FastAPI + PyTorch + Jinja2 + Alpine.js + htmx  
> **评估日期**：2026-08-10  
> **综合评分**：**95 / 100** ⭐⭐⭐⭐⭐ — 5个项目中的标杆，极其完善

## 一、项目概览

| 属性 | 内容 |
|------|------|
| 项目名称 | TTS MultiModel - 多模型语音合成平台 |
| 一句话描述 | 基于 VoxCPM2 + IndexTTS 2.5 + dots.tts 的开源 TTS 平台，支持声音克隆、声音设计、LoRA 微调与剧本配音 |
| 前端技术 | HTML + Jinja2 + Alpine.js 3 + htmx + 原生 JS（模块化拆分，20+ 个 JS 文件） |
| 后端技术 | Python FastAPI + Uvicorn + 多引擎接口抽象层 |
| 数据库 | SQLite（aiosqlite 异步驱动） |
| AI/ML | VoxCPM2 / IndexTTS 2.5 / dots.tts 三引擎，支持 LoRA 微调 + 声音克隆 + 流式输出 |
| 包管理 | pip（requirements.txt + pyproject.toml + optional-dependencies） |
| 开源协议 | Apache-2.0 |
| 当前版本 | v2.2.0 |

## 四、缺失要素清单（按优先级）

这个项目太完善了，缺失的都是**锦上添花**的 P2 级内容：

### 🟡 中优先级（本月内完成，可选）

| # | 缺失项 | 优先级 | 建议位置 | 说明 |
|---|--------|:------:|----------|------|
| 1 | **perf/ 性能监控脚本目录** | 🟡 中 | 新建 perf/ 目录 | 目前的 benchmark 在 tests/benchmarks/ 里，都是 pytest 格式的集成测试。可以参考 PetPal 的 perf/ 目录，补一些独立的 Node.js/Python 性能监控脚本：<br>• **cold-start.py**：记录从启动到 API 可响应的时间（冷启动很重要，TTS 模型加载慢）<br>• **vram-usage.py**：持续监控不同引擎切换时的显存占用（画成图表）<br>• **generation-benchmark.py**：批量测不同文本长度/不同说话人的生成速度（RTF 实时率 = 生成时间/音频时长）<br>• **stress-test.py**：并发 5/10/20 路请求压测，看 QPS 和错误率 |
| 2 | **AGENTS.md** | 🟡 中 | 项目根目录 | 5 个项目里 PetPal 和 DraftPeek 都有 AGENTS.md，唯独这个项目没有。如果你也用 AI 辅助开发，建议写一个，包含：<br>• 代码风格：ruff 规则 + mypy 严格程度、测试覆盖率分阶段目标<br>• 模块边界：engines/ 是引擎接口抽象层、routes/ 只放路由逻辑不写业务、training/ 是训练独立模块<br>• 测试约定：新功能必须补 test_、集成测试放 tests/integration、e2e 放 tests/e2e<br>• 发布流程：release-please 自动生成版本，PR 要用 Conventional Commits 格式（feat/fix/docs/...） |
