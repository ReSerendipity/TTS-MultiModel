# 性能门禁的判据与噪声地板（issue #118 的落点）

这条门禁在 2026-09-22 之前会在**与改动无关**的 PR 上随机变红。修完之后它只判一件事：
**同一批基准的 `median` 相对 `main` 基线变慢超过 50% 才算回退。**

## 为什么阈值是 50%，不是 20%

共享 runner 上这些是微秒/毫秒级的微基准。**同一份代码**（两次 run 之间只差一个
`docs/DOD.md`）的 mean 摆动实测就有 17%–80%：

| benchmark | 成功那次 | 失败那次 | 偏差 | 重跑 | 偏差 |
|---|---|---|---|---|---|
| `test_adaptive_cache_capacity_adaptation` | 0.000088 | 0.000072 | −18.6% | 0.000070 | −20.7% |
| `test_audio_merge_performance` | 0.058784 | 0.012027 | **−79.5%** | 0.047191 | −19.7% |
| `test_cache_hit_miss_latency` | 0.000590 | 0.000406 | −31.2% | 0.000419 | −29.0% |
| `test_cache_operations_performance` | 0.001525 | 0.001101 | −27.8% | 0.001130 | −25.9% |
| `test_text_splitting_performance` | 0.188862 | 0.156183 | −17.3% | 0.158885 | −15.9% |

旧门槛是 `--benchmark-compare-fail=mean:20%`，而且**双向**判：上面这些被判"回退"的例子
全是**变快**（负值 = 耗时下降）。用噪声当信号，红不红全看运气。

## 三个机制缺陷各自变成了什么

| 缺陷 | 旧行为 | 现在 |
|---|---|---|
| 基线来源 | `find … \| grep -v "ci-<本次 sha>"` 只排除本次 sha，**同一 PR 两分钟前的 run 会被当成历史基线**（自己和自己比） | 缓存 `restore-keys` 只留 `benchmark-storage-refs/heads/main`，拿不到 main 基线就"仅记录、不判回归"；裸前缀那条被 `tests/test_benchmark_gate.py` 禁掉 |
| 判据 | `mean`、±20%、变快也红 | `median`、单向、>50% 才红；变快不判失败 |
| 可读性 | 整段 `>> $GITHUB_STEP_SUMMARY 2>&1 \|\| exit 1`，日志里只有 `exit code 1`，6 秒结束 | 不重定向，逐条打印 `基线 median / 本轮 median / 变化% / 判定` 表；本轮结果没存下来时按**流程错误**硬失败（不是"没数据=通过"） |

## 想改这里先看这两条

1. 阈值再往下压之前，先在同一条 main 上连跑几次拿真实摆动分布 —— 50% 是"承认噪声地板"，
   不是"允许回退 49%"。要抓更小的回退，办法是加轮次/换机器，不是调阈值。
2. 门禁逻辑本身有测试：`tests/test_benchmark_gate.py` 会从 `benchmark.yml` 里**抽出那段
   真正在 CI 跑的 heredoc**，喂 5 种场景（噪声 ±30% 应过、+200% 应红且指名哪条基准、
   变快应过、无 main 基线应仅记录、本轮缺结果应硬失败）。改脚本不改测试会红，
   改测试而不改脚本也会红 —— 别把这两半拆开。
